1How to approach DSA + Big-O

Definition

Data structure = a way to store & organise data (array, object/dict, set, stack…). Algorithm = a step-by-step recipe to solve a problem. DSA = picking the right structure + recipe so the solution is correct and fast.

My 5-step problem-solving routine

  1. Understand — restate the problem; inputs? outputs? sorted? negatives? empty input?
  2. Examples — simple case, edge cases ([], one item, duplicates, no answer).
  3. Brute force first — any working solution, say its Big-O out loud.
  4. Optimise — look for a pattern: frequency counter, two pointers, sliding window, divide & conquer.
  5. Refactor & test — clean names, re-run the examples, state final time + space.

Big-O = how work grows with input size n

Big-O rules

  • Drop constants: O(2n) → O(n). O(500) → O(1).
  • Keep the biggest term: O(n² + n) → O(n²).
  • Loops one after another add (O(n + n) = O(n)); loops inside each other multiply (O(n · n) = O(n²)).
  • We talk about the worst case unless told otherwise.
  • Space complexity = extra memory the algorithm uses (a new dict of n keys → O(n); a few variables → O(1)).

2The 4 problem-solving patterns

Why patterns?

Most beginner/intermediate array & string questions are solved by turning an O(n²) nested loop into O(n) using one of these 4 tricks. The whole playlist is built around them.
PatternIdeaSignal in the questionUsed in
Frequency counterCount things in a dict/object, then compare counts instead of nested loops."same letters", "same frequency", "most common", compare two collectionsAnagram, Squares, Max char
Multiple / two pointersTwo indexes moving towards each other or in the same direction based on a condition.Sorted array, pairs, "in place", palindromeSum Zero, Count Unique, Palindrome
Sliding windowKeep a window (start…end) over the data; slide it instead of recomputing."consecutive", "subarray / substring", "longest / max of size k"Largest sum, Longest substring

Two pointers shape

    # decide: left += 1 or right -= 1

Compare/count → frequency counter. Sorted + pairs → two pointers. Consecutive / substring → sliding window. Sorted + find fast → divide & conquer.

3Sum Zerovideo #1, #2

Problem

Given a sorted array of integers, return the first pair whose sum is 0. If no pair, return None / undefined.
[-4,-3,-2,-1,0,1,2,5] → [-2, 2] · [-3,-2,-1,0,5] → none

Way 1 · Brute force — O(n²)

Check every pair with two nested loops.

python
def sum_zero_brute(arr):            # O(n^2)
    for i in range(len(arr)):
        for j in range(i + 1, len(arr)):
            if arr[i] + arr[j] == 0:
                return [arr[i], arr[j]]
    return None
javascript
function sumZeroBrute(arr) {        // O(n^2)
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] + arr[j] === 0) {
        return [arr[i], arr[j]];
      }
    }
  }
  return undefined;
}

def sum_zero(arr):                  # sorted input
    left, right = 0, len(arr) - 1   # O(n), O(1)
    while left < right:
        total = arr[left] + arr[right]
        if total == 0:
            return [arr[left], arr[right]]
        elif total > 0:
            right -= 1              # need smaller
        else:
            left += 1               # need bigger
    return None
javascript
function sumZero(arr) {             // sorted input
  let left = 0;                     // O(n), O(1)
  let right = arr.length - 1;
  while (left < right) {
    const sum = arr[left] + arr[right];
    if (sum === 0) return [arr[left], arr[right]];
    else if (sum > 0) right--;      // need smaller
    else left++;                    // need bigger
  }
  return undefined;
}

Mistake

Using left <= right → when they meet you add the same element to itself (0 + 0 = 0 gives a wrong pair [0, 0]). Use left < right. And two pointers only work because the array is sorted.

Revision

Sorted + find a pair → two pointers from both ends. Sum too big → right--, too small → left++. O(n²) → O(n).

4Valid Anagramvideo #3

Problem

Two strings are anagrams if they use exactly the same letters, the same number of times, in any order.
"anagram", "nagaram" → true · "rat", "car" → false · "aaz", "zza" → false

python
def is_anagram(a, b):               # O(n)
    if len(a) != len(b):
        return False
    freq = {}
    for ch in a:                    # count a
        freq[ch] = freq.get(ch, 0) + 1
    for ch in b:                    # use up with b
        if not freq.get(ch):
            return False
        freq[ch] -= 1
    return True

# one-liner: Counter(a) == Counter(b)
javascript
function isAnagram(a, b) {          // O(n)
  if (a.length !== b.length) return false;
  const freq = {};
  for (const ch of a) {             // count a
    freq[ch] = (freq[ch] || 0) + 1;
  }
  for (const ch of b) {             // use up with b
    if (!freq[ch]) return false;
    freq[ch]--;
  }
  return true;
}
Python: Counter(a) == Counter(b). JS has no Counter → memorise freq[ch] = (freq[ch] || 0) + 1.

Mistake

Forgetting the length check first, and checking only "does b's char exist in a" (that says "aaz" and "zza" match). Counts matter, not just presence. Ask the interviewer about case & spaces ("Dormitory" vs "dirty room").

Revision

Anagram = same chars, same counts. Length check → count first string → decrement with second → any miss = false. O(n).

def count_unique(arr):              # sorted input
    if not arr:                     # O(n), O(1)
        return 0
    i = 0                           # last unique
    for j in range(1, len(arr)):

javascript
function countUnique(arr) {         // sorted input
  if (arr.length === 0) return 0;   // O(n), O(1)
  let i = 0;                        // last unique
  for (let j = 1; j < arr.length; j++) {
    if (arr[j] !== arr[i]) {
      i++;
      arr[i] = arr[j];              // move it forward
    }
  }
  return i + 1;
}

// easy way (O(n) extra space): new Set(arr).size

Mistake

Returning i instead of i + 1 (i is an index), and crashing on an empty array. This version modifies the input — say so in an interview, or use a counter instead of copying.

Revision

Sorted → duplicates are neighbours. i = last unique, j scans; new value → i++ and copy. Answer i + 1. O(n) time, O(1) space. Shortcut: len(set(arr)) / new Set(arr).size (O(n) space).

6Largest Sum of Consecutive Elementsvideo #5

Problem

Given an array and a number k, find the maximum sum of k consecutive elements.
[2,6,9,2,1,8,5,6,3], k=3 → 19 (8 + 5 + 6)

Way 1 · Brute force — O(n·k)

For every starting index, add up the next k numbers again from scratch.

python
def max_sum_brute(arr, k):          # O(n*k)
    if len(arr) < k:
        return None
    best = float('-inf')
    for i in range(len(arr) - k + 1):
        best = max(best, sum(arr[i:i + k]))
    return best
javascript
function maxSumBrute(arr, k) {      // O(n*k)
  if (arr.length < k) return null;
  let best = -Infinity;
  for (let i = 0; i <= arr.length - k; i++) {
    let sum = 0;
    for (let j = 0; j < k; j++) sum += arr[i + j];
    best = Math.max(best, sum);
  }
  return best;
}

def max_sum(arr, k):                # O(n)
    if len(arr) < k:
        return None
    window = sum(arr[:k])           # first window
    best = window

javascript
function maxSum(arr, k) {           // O(n)
  if (arr.length < k) return null;
  let window = 0;
  for (let i = 0; i < k; i++) window += arr[i];
  let best = window;                // first window
  for (let i = k; i < arr.length; i++) {
    window += arr[i] - arr[i - k];  // slide
    best = Math.max(best, window);
  }
  return best;
}

Mistake

Starting best = 0 — wrong when all numbers are negative ([-3,-1,-2], k=2 → -3). Start from the first window (or -∞). And handle len(arr) < k.

Revision

"k consecutive" → fixed sliding window. Sum first k, then slide: + arr[i] − arr[i−k], track max. O(n·k) → O(n), O(1) space.

Definition

Divide & conquer = break a problem into smaller pieces, solve the piece that matters, ignore the rest. Binary search applies it to a sorted array: look at the middle, then throw away the half that can't contain the target. Real life: finding a word in a dictionary — open the middle, go left or right.

python
def binary_search(arr, target):     # O(log n)
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1            # go right
        else:
            hi = mid - 1            # go left
    return -1
javascript
function binarySearch(arr, target) { // O(log n)
  let lo = 0, hi = arr.length - 1;
  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2);
    if (arr[mid] === target) return mid;
    if (arr[mid] < target) lo = mid + 1; // right
    else hi = mid - 1;                   // left
  }
  return -1;
}
  • Best O(1) (first middle) · worst / average O(log n) (halves every step) · space O(1) iterative, O(log n) recursive.

Mistakes

  • while lo < hi misses the last element → use lo <= hi.
  • lo = mid / hi = mid → infinite loop; always mid + 1 / mid - 1.
  • JS: (lo + hi) / 2 is a decimal → wrap in Math.floor. Python: use //.
  • Running it on unsorted data gives wrong answers.

Revision

Sorted + search → binary search. lo, hi, mid; equal → return; smaller → lo = mid+1; bigger → hi = mid−1; loop while lo ≤ hi. O(log n). Python built-in: bisect.bisect_left(arr, x).

8Squares in Another Arrayvideo #7, #8

Problem

Write same(a, b) → true if every value in a has its square in b, with the same frequency. Order doesn't matter.
[1,2,3,2], [9,1,4,4] → true · [1,2,3], [1,9] → false · [1,2,1], [4,4,1] → false (frequencies differ)

Way 1 · Brute force — O(n²)

For each x in a, search for x² in b (that search is itself a loop) and remove it so it can't be reused.

python
def same_brute(a, b):               # O(n^2)
    if len(a) != len(b):
        return False
    b = list(b)                     # don't mutate input
    for x in a:
        if x * x not in b:          # .index is O(n)
            return False
        b.remove(x * x)
    return True
javascript
function sameBrute(a, b) {          // O(n^2)
  if (a.length !== b.length) return false;
  b = [...b];                       // don't mutate input
  for (const x of a) {
    const idx = b.indexOf(x * x);   // O(n) scan
    if (idx === -1) return false;
    b.splice(idx, 1);
  }
  return true;
}

Way 2 · Frequency counter — O(n)

def same(a, b):                     # O(n)
    if len(a) != len(b):
        return False
    fa, fb = {}, {}
    for x in a:
        fa[x] = fa.get(x, 0) + 1
    for y in b:

javascript
function same(a, b) {               // O(n)
  if (a.length !== b.length) return false;
  const fa = {}, fb = {};
  for (const x of a) fa[x] = (fa[x] || 0) + 1;
  for (const y of b) fb[y] = (fb[y] || 0) + 1;
  for (const key in fa) {
    if (fb[key * key] !== fa[key]) return false;
  }
  return true;
}

Mistake

Brute force with indexOf / in looks like one loop but is O(n²) — the search hides a second loop. And don't mutate the caller's array with splice / remove; copy it first.

Revision

Compare two collections by value + count → two frequency maps, then compare keys. Three separate loops = O(3n) = O(n). Space O(n).

9Recursion basicsvideo #9

Definition

Recursion = a function that calls itself on a smaller version of the problem until it reaches a case it can answer directly. Real life: Russian dolls — open one, there's a smaller one inside, until the tiniest doll.

Every recursive function needs 2 things

1 · Base case

The stopping condition — returns without calling itself. No base case = infinite recursion.

2 · Smaller input

Each call must move closer to the base case (n − 1, slice(1), half…).
python
def countdown(n):
    if n <= 0:                      # 1. base case
        print("Done!")
        return
    print(n)
    countdown(n - 1)                # 2. smaller input
javascript
function countdown(n) {
  if (n <= 0) {                     // 1. base case
    console.log("Done!");
    return;
  }
  console.log(n);
  countdown(n - 1);                 // 2. smaller input
}
python
def factorial(n):                   # O(n) time+stack
    if n <= 1:
        return 1
    return n * factorial(n - 1)

def sum_range(n):                   # 1 + 2 + ... + n
    if n == 1:
        return 1
    return n + sum_range(n - 1)
javascript
function factorial(n) {             // O(n) time+stack
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}

function sumRange(n) {              // 1 + 2 + ... + n
  if (n === 1) return 1;
  return n + sumRange(n - 1);
}

The call stack — factorial(4)

Mistakes

  • No / wrong base case → RecursionError (Python, default limit ~1000) / RangeError: Maximum call stack size exceeded (JS).
  • Forgetting to return the recursive result — factorial(n - 1) without return gives None / undefined.
  • Input that never shrinks (calling with n instead of n - 1).

Revision

Base case + smaller input + return the result. Each call waits on the stack until the base case answers, then results bubble back up. Stack space = O(depth).

10Advanced recursionvideo #10

The recipe

Ask: "If someone solved the smaller problem for me, how do I finish?" — power(b, e) = b × power(b, e−1); product(arr) = arr[0] × product(rest); fib(n) = fib(n−1) + fib(n−2).
python
def power(base, exp):
    if exp == 0:
        return 1
    return base * power(base, exp - 1)

def product(arr):
    if not arr:
        return 1
    return arr[0] * product(arr[1:])

def fib(n):                         # O(2^n)!
    if n <= 2:
        return 1
    return fib(n - 1) + fib(n - 2)
javascript
function power(base, exp) {
  if (exp === 0) return 1;
  return base * power(base, exp - 1);
}

function product(arr) {
  if (arr.length === 0) return 1;
  return arr[0] * product(arr.slice(1));
}

function fib(n) {                   // O(2^n)!
  if (n <= 2) return 1;
  return fib(n - 1) + fib(n - 2);
}

Why naive Fibonacci is slow

Fix · memoisation — remember answers

python
def fib_memo(n, memo=None):         # O(n)
    memo = {} if memo is None else memo
    if n <= 2:
        return 1
    if n not in memo:
        memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]
javascript
function fibMemo(n, memo = {}) {    // O(n)
  if (n <= 2) return 1;
  if (memo[n]) return memo[n];
  memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
  return memo[n];
}

Recursion on strings

python
def reverse(s):
    if len(s) <= 1:
        return s
    return reverse(s[1:]) + s[0]
javascript
function reverse(s) {
  if (s.length <= 1) return s;
  return reverse(s.slice(1)) + s[0];
}
Python shortcut for memo: @functools.lru_cache(maxsize=None) on top of the plain fib. Memoisation is the first step into Dynamic Programming.

Mistake

Slicing (arr[1:], arr.slice(1), s[1:]) copies the array every call → hidden O(n) per call, O(n²) total. Fine for learning; in interviews mention passing an index instead.

Revision

Trust the smaller call, finish the last step. Fibonacci tree repeats work → memo with a dict/object turns O(2ⁿ) into O(n).

11Helper-method recursionvideo #12

Definition

A helper method pattern = an outer function that holds the result (array, counter) and an inner recursive function that does the work and writes into it. Useful when you need to collect things — because a plain recursive call would reset the result every time.

Problem: collect all odd numbers from an array. [1,2,3,4,5] → [1,3,5]

python
def collect_odds(arr):
    result = []                     # outer state

    def helper(sub):                # recursive helper
        if not sub:
            return
        if sub[0] % 2 != 0:
            result.append(sub[0])
        helper(sub[1:])

    helper(arr)
    return result
javascript
function collectOdds(arr) {
  const result = [];                // outer state

  function helper(sub) {            // recursive helper
    if (sub.length === 0) return;
    if (sub[0] % 2 !== 0) result.push(sub[0]);
    helper(sub.slice(1));
  }

  helper(arr);
  return result;
}

Same thing with pure recursion

No outer variable: each call returns its piece; pieces join on the way back. Helper: the result lives outside the recursion, so it isn't reset each call.

python
def collect_odds_pure(arr):
    if not arr:
        return []
    first = [arr[0]] if arr[0] % 2 else []
    return first + collect_odds_pure(arr[1:])
javascript
function collectOddsPure(arr) {
  if (arr.length === 0) return [];
  const first = arr[0] % 2 !== 0 ? [arr[0]] : [];
  return first.concat(collectOddsPure(arr.slice(1)));
}

Revision

Need to collect results? Outer function keeps the list, inner helper recurses and appends. Or pure recursion: return [piece] + recurse(rest).

12Searching — Linear vs Binaryvideo #13, #14

Definition

Searching = finding the position of a value in a collection. Linear search checks items one by one from the start — works on any array. Real life: looking for your friend in a queue, person by person.

function selectionSort(arr) {       // O(n^2)
  const n = arr.length;

Swapping inside the inner loop every time you see a smaller value — that's not selection sort (and does many more swaps). Track the index of the minimum, swap once after the inner loop.

def insertion_sort(arr):            # O(n^2), best O(n)
    for i in range(1, len(arr)):

function insertionSort(arr) {       // O(n^2), best O(n)
  for (let i = 1; i < arr.length; i++) {

    let j = i - 1;

      j--;
    }
    arr[j + 1] = current;           // drop in the gap
  }
  return arr;
}

function maxChar(s) {               // O(n)
  const freq = {};
  for (const ch of s) freq[ch] = (freq[ch] || 0) + 1;
  let best = "", bestCount = 0;

function isPalindrome(s) {          // O(n), O(1)
  let left = 0, right = s.length - 1;
  while (left < right) {
    if (s[left] !== s[right]) return false;
    left++;
    right--;
  }
  return true;
}

def longest_unique(s):              # O(n)
    last_seen = {}                  # char -> index
    start = best = 0

javascript
function longestUnique(s) {         // O(n)
  const lastSeen = new Map();       // char -> index
  let start = 0, best = 0;
  for (let end = 0; end < s.length; end++) {
    const ch = s[end];
    if (lastSeen.has(ch) && lastSeen.get(ch) >= start) {
      start = lastSeen.get(ch) + 1; // jump past dup
    }
    lastSeen.set(ch, end);
    best = Math.max(best, end - start + 1);
  }
  return best;
}

Mistake — the "abba" trap

Without the check last_seen[ch] >= start, the window can move backwards: at the last 'a' in "abba", 'a' was seen at 0, which is already outside the window (start = 2). Jumping to 0 + 1 = 1 would wrongly give 3. Only jump if the duplicate is inside the current window (or use start = max(start, seen + 1)).

Revision

Variable sliding window: expand end every step; on a duplicate inside the window, move start to last_seen + 1; record last_seen; best = max(best, end − start + 1). O(n) time, O(k) space.

Rapid-fire Q&A

Q. What is Big-O?

A. How the number of steps (or memory) grows as input size n grows — worst case, constants dropped.

Q. O(n) vs O(log n) on 1 million items?

A. ~1,000,000 steps vs ~20 steps.

Q. When do two pointers work?

A. Usually on sorted arrays or when comparing both ends (pairs, palindrome, in-place dedupe).

Q. Frequency counter in one line?

A. Count items in a dict/object, then compare counts — replaces nested loops, O(n).

Q. Fixed vs variable sliding window?

A. Fixed: size k given (max sum of k). Variable: grows/shrinks by a rule (longest substring without repeats).

Q. Why does binary search need sorted data?

A. Discarding half is only safe if everything on one side is known to be smaller/bigger.

Q. Two must-haves of recursion?

A. A base case and a smaller input on every call (and return the result).

Q. Why is naive fib slow and how to fix?

A. Recomputes the same subproblems → O(2ⁿ). Memoise → O(n).

Q. Helper method recursion?

A. Outer function holds the result, inner recursive helper fills it.

Q. Bubble vs selection vs insertion in one line each?

A. Bubble: swap neighbours, max goes to end. Selection: pick min, swap to front. Insertion: insert next item into sorted left part.

Q. Which simple sort for nearly-sorted data?

A. Insertion sort (O(n) best case). Optimised bubble also O(n) best case.

Q. What does stable sort mean?

A. Equal elements keep their original relative order.

Q. Why is [10,1,5].sort() wrong in JS?

A. Default sort compares strings; pass (a, b) => a - b.

Q. Substring vs subsequence?

A. Substring = contiguous; subsequence = order kept, gaps allowed.
